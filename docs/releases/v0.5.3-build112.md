# iPac 0.5.3 / Build 112

日期：2026-11-26（台北）。本機效能預覽版，未發布至 GitHub。

## 本版改動

- **降低 CPU 診斷負擔**：一般執行不再開啟詳細 CPU／記憶體轉譯統計。舊預設會在虛擬 CPU 0 上定期掃描約 210 萬個快取桶。基本效能摘要仍保留；開發除錯時可在 App 的 `Documents/henge-env.txt` 設定 `HV_STATS=10`，於下次啟動 VM 套用。
- **減少 GPU 建立畫面資源時的工作**：Metal 後端將來源與目的位址皆連續的 16 KiB 頁面合併成一段 Mach 記憶體映射，不再固定每頁呼叫一次。改善的是建立映射的成本，不更動來賓解析度、顯示品質或 iPad 硬體驅動。
- **不替關閉的面板更新資料**：只有展開「詳細資訊」時才每秒更新 CPU、網路與最近 30 行日誌。平時保留較低頻的效能摘要，依實際經過時間回報 GPU 畫面更新次數；這不是面板實際顯示的 FPS。

## 驗證範圍

Mac 端的 Mach 映射測試衡量的是映射呼叫數及建立映射的耗時。這些結果不能換算為 iPad 上拖曳視窗的 FPS、輸入延遲或整體流暢度，也不能據此判定舊版變卡只有一個原因。本版不會為了測試自動改寫既有 VM 的 RAM 或 CPU 設定。

## 升級與比較

1. 先在舊版恢復 VM、儲存工作，再從來賓 macOS 的蘋果選單正常關機；不要把舊版快照當作跨版本升級方式。
2. 檔名為 `iPac-v0.5.3-build112.ipa`。IPA 為 ad-hoc 簽名；請用與舊版相同的開發 Team 重新簽署後覆蓋更新，不要先刪除 App。
3. 先保留原設定驗證同一段桌面操作。若要比較 8 與 6 個虛擬 CPU，每次先正常關機，只改核心數，固定 RAM、解析度及更新率，在相近溫度下重做同樣的捲動或拖曳。更多虛擬核心不保證更順。
